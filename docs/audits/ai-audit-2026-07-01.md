## Findings

### Phase 2 — Security & privacy

### [XSS-001] Stored XSS via unescaped JSON-LD injection on public pages
- Severity: **High**
- Pass:     A (XSS)
- Location: `app/(public)/adoptar/[petToken]/page.tsx:221`; same pattern at
  `app/(public)/refugios/[orgToken]/page.tsx:184`, `app/(public)/denuncias/codigo/[code]/page.tsx:131`
- Status:   **Confirmed** (pattern) / Suspected (exploitability — depends on whether `pet.name` /
  `pet.adoptionStory` / org fields are sanitized on write; verify)
- Evidence: `dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}` where `jsonLd` embeds
  user-controlled `pet.name` and `pet.adoptionStory`. `JSON.stringify` does **not** escape `<`, so a
  value containing `</script><script>…` breaks out of the JSON-LD block. The `biome-ignore` comment
  asserts "controlled object, not user data" — but pet name and adoption story **are** user data.
- Impact:   Stored XSS on unauthenticated public pages of a government-adjacent app — session theft,
  defacement, credential-page tampering.
- Fix (unapplied): escape the serialized output before injecting, e.g.
  `JSON.stringify(jsonLd).replace(/</g, '\\u003c').replace(/>/g, '\\u003e').replace(/&/g, '\\u0026')`,
  or route through a hardened JSON-LD serializer. Apply to all three pages. Then correct the
  `biome-ignore` justification.

### [HDR-001] No security response headers configured
- Severity: **Medium** (defense-in-depth; compounds XSS-001 — a CSP would blunt it)
- Pass:     A (headers)
- Location: `next.config.ts` (no `headers()`), `vercel.json` (no `headers` block)
- Status:   Confirmed
- Evidence: `next.config.ts` defines `images`/`experimental` only; `rg` for
  `Content-Security-Policy|X-Frame-Options|Strict-Transport-Security|X-Content-Type-Options` in
  `next.config.ts` and `vercel.json` returns nothing.
- Impact:   No CSP, clickjacking protection, MIME-sniffing protection, or HSTS on a PII/gov app.
- Fix (unapplied): add a `headers()` entry in `next.config.ts` (or `vercel.json`) with
  `Content-Security-Policy`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security`,
  `Permissions-Policy`.

### [KEY-001] Local service_role key hardcoded in tests and .claude/settings.local.json
- Severity: **Low** (it is the **local** Supabase key — `NEXT_PUBLIC_SUPABASE_URL=localhost:54321`, not a
  production secret)
- Pass:     A (secrets)
- Location: `__tests__/setup.ts:23` (`LOCAL_SERVICE_KEY`) and ~40 `__tests__/*.test.ts` files;
  `.claude/settings.local.json` (embedded inline in a Bash allow-pattern)
- Status:   Confirmed
- Evidence: `const SECRET = "sb_secret_<redacted, len 44>"` repeated across tests; the same value is
  inlined in `.claude/settings.local.json`. Value redacted per policy.
- Impact:   Low while it stays local-only. Risk if the key is ever reused for staging/shared projects,
  or normalizes committing service keys. `service_role` bypasses RLS.
- Fix (unapplied): centralize the local key in one test helper / env fixture; remove the literal from
  `.claude/settings.local.json`; ensure that file stays gitignored; never reuse this key off-localhost.

### [RNG-001] Math.random() used for storage-path suffixes
- Severity: **Low** (non-secret use — filenames, not auth tokens)
- Pass:     A (RNG)
- Location: `app/gob/usuarios/RevokeUserActions.tsx:129`, `app/gob/organizaciones/RevokeOrgActions.tsx:134`,
  `lib/domain/revocation-evidence-path.ts:31`
- Status:   Confirmed
- Evidence: path = `` `${actorUserId}/${Date.now()}-${Math.random().toString(36).slice(2)}.${ext}` ``
- Impact:   Predictable/low-entropy suffixes. Not a token, and prefixed by `actorUserId` + timestamp, so
  low risk — but if the evidence bucket is public and listable, filenames could be guessable.
- Fix (unapplied): prefer `crypto.randomUUID()` for the suffix (the codebase already uses it elsewhere).
