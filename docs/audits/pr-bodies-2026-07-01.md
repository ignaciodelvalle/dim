## PR 1 — `fix/jsonld-xss-and-security-headers` → `chore/tech-debt-finish`

**Title:** `fix(security): escape JSON-LD (XSS-001) + baseline security headers (HDR-001)`

**Body:**

Closes the two actionable findings from the 2026-07-01 audit (`docs/audits/ai-audit-2026-07-01.md`).

### XSS-001 (High) — stored XSS via unescaped JSON-LD
Public pages embedded user free-text (pet name/adoption story, org name/description/legalName) into
`<script type="application/ld+json">` via `JSON.stringify()`, which does **not** escape `<`, `>`, `&`, or
the U+2028/U+2029 line separators — so a value containing `</script>…` could break out of the inline script
on unauthenticated, government-adjacent pages.

- New `lib/utils/json-ld.ts` → `serializeJsonLd()`: emits JSON-safe unicode escapes for those characters
  (not HTML-entity escaping — the payload is parsed as JSON). Output still round-trips to the original
  object. Covered by `lib/utils/json-ld.test.ts` (3 tests).
- `app/(public)/adoptar/[petToken]/page.tsx` and `app/(public)/refugios/[orgToken]/page.tsx` now route
  their JSON-LD through it; misleading `biome-ignore` rationales corrected.
- Out of scope (verified safe): `denuncias/codigo/[code]/page.tsx` (static print `<style>`, no user input);
  `qrSvg` server-generated markup.

### HDR-001 (Medium) — baseline security headers
`next.config.ts` now sets, for all routes: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`,
`Referrer-Policy: strict-origin-when-cross-origin`, `Strict-Transport-Security` (2y, preload), and a
conservative `Permissions-Policy`. **No `Content-Security-Policy`** on purpose — a correct CSP needs
per-request nonces/hashes for the inline JSON-LD and inline styles; a naive policy would break rendering.
CSP is a tracked follow-up.

### Verification
`pnpm typecheck` ✓ · `pnpm lint` ✓ (1966 files) · `pnpm test lib/utils/json-ld.test.ts` ✓ 3/3 ·
`pnpm build` ✓ (headers accepted, both pages compile). `rg 'JSON.stringify(jsonLd)' app` → empty.

### Follow-up (not in this PR)
Design a real Content-Security-Policy with nonces for inline JSON-LD + inline styles.

## PR 2 — `fix/test-stale-vimock-paths` → `chore/tech-debt-finish`

**Title:** `fix(test): repoint stale test paths left by the lib/ bucketize refactor`

**Body:**

The `refactor(lib): bucketize` change moved dozens of `lib/*.ts` modules into
`lib/{infra,domain,analytics,ui,events,reference,utils}/*.ts` and updated the source imports — but the
**string-literal paths inside tests** were left on the old, now-deleted locations. tsc and Biome don't
resolve those literals, so the breakage passed the gate silently and `pnpm test` sat at **258 failing**.

Three mechanisms, all repointed (string-literal changes only — no source, no imports, no assertions):
- `vi.mock("@/lib/X")` — 40 specifiers, 104 occurrences, 36 files. Each stale mock targeted a dead module,
  so the real module ran unmocked and `vi.mocked(fn).mockResolvedValue/mockRejectedValue` threw
  `is not a function`.
- `vi.doMock()/vi.doUnmock("@/lib/X")` — 9 specifiers, 52 occurrences, 11 files (mostly cron-route tests).
  e.g. tests `doMock`ed `@/lib/notifications` while the route imports `@/lib/infra/notifications`, so the
  scan helper ran unmocked and hit the DB (auth-passing cases returned 500/401 or wrong shapes).
- `readFileSync(".../lib/X.ts")` — 2 files: `link-integrity` (→ `lib/events/…`), `demo-mode` (→ `lib/domain/…`).

Every stale specifier mapped 1:1 by basename to exactly one bucketized location (0 ambiguous).

### Result
`pnpm test`: **258 → 2 failed** (`2 failed | 6805 passed`). The remaining 2
(`pet-cache-rederivation`, `admin-analytics-perf`) are **local-Supabase integration tests**
(`127.0.0.1:54321`, `db.insert`/`db.transaction`, a 3 s perf budget) — they need `pnpm db:start` + seed
and are unrelated to this change (tracked separately). `pnpm typecheck` ✓ · `pnpm lint` ✓.

### Why it's low-risk
Diff is `*.test.ts(x)` only; every hunk is a quoted path string. No production code path changes.
