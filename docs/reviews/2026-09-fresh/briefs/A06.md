# A06 brief — Privacy and PII flows

## Contract

Read-only audit. Do not edit, format, run, or commit anything in the repo; do not run `pnpm`, tests, or builds. Confirm you are on `main` at the pinned SHA before starting (`git rev-parse HEAD` should print `d7dbf25f7`, or note the delta if it has moved and re-anchor line numbers accordingly). Exclusions: `node_modules`, build output, and anything under `docs/reviews/` itself are out of scope as audit targets (they may be read as priors). Every claim in your output must carry an `evidenceCmd` runnable by hand and the literal output lines it produced — never a paraphrase, never a number recalled from memory.

## Method

1. **Enumerate the surface.** Run the scope's `rg` commands verbatim (DNI grep, console.* grep, Sentry hook grep) before reading anything — they define what "every reader" means for this pass. Also list: every table under `db/schema.ts` touched by the `pii` schema; every exported fetcher in `lib/metrics/` and `lib/analytics/` that does a `groupBy` on a jurisdiction/locality column; every route under `app/(public)/` that renders event/pet/owner free text; the mobile observability directory in full.

2. **One command per claim.** For every claim you intend to make (finding or healthy), the `evidenceCmd` must be the exact command you ran (`rg -n '...' path`, or `Read path:start-end`) and `evidenceOutput` the literal lines returned — not a summary. If a claim rests on "no matches", show the command and note the empty/nonzero exit, don't just assert absence.

3. **Count with the fence's own method.** For k-anonymity claims, don't just read the suppression function — check every declared return type against `lib/metrics/types.ts`'s `MetricResult<SuppressedCells>` convention, and check whether the type-level brand actually binds the fetcher in question (a function that declares a different return type is unfenced even if a sibling function is fenced). For log/report claims, grep the full call-site list (`rg -n 'console\.'` or `rg -n 'reportError'` etc.) and account for every hit, not a sample.

4. **Every finding needs an exploit or a mutation.** State the smallest concrete input, actor, or one-line code edit that turns the gap into a live disclosure — and check whether that edit is already unopposed (no lint fence, no type brand, no test) or whether some other layer (a caller, a WHERE clause, a consent gate) already closes it. If a caller closes it, say so and lower severity accordingly rather than dropping the finding.

5. **At least 3 healthy-with-guard items.** For each, name the property in one falsifiable sentence, the file:line that enforces it, the specific test file(s) that would fail if it broke (open the test and confirm it actually asserts the property — a `guardedBy` citation that doesn't cover the claimed property is a claimed-healthy-not-verified item, not a verified one), and one concrete edit that would break it silently.

6. **Triage every prior.** For each of the 17 prior items: re-run its original evidence command against the current SHA. Mark `closed` (the code no longer has the gap), `still-open` (same gap reproduces), or `not-reproducible` (couldn't establish either way — say why). Fold still-open items into fresh findings rather than restating them verbatim if the underlying code has moved.

7. **Severity rubric** (apply after establishing exploit/impact, not before):
   - **CRITICAL** — unauthenticated or cross-tenant disclosure of DNI, phone, address, or other directly-identifying PII, live today.
   - **HIGH** — authenticated but wrong-role disclosure, or an unauthenticated disclosure of sensitive-but-not-directly-identifying data (free-text notes about a third party, precise location).
   - **MED** — a real fence gap or missing scrub with no live leak today (a caller/type/consent boundary currently closes it, but nothing prevents a future caller from opening it), OR a live disclosure whose subject is also its own publisher/consenter.
   - **LOW** — hygiene: a convention documented but not enforced, with a plausible-but-not-demonstrated path to harm, or a MED-shaped issue further mitigated by scope/consent/authentication layers.
   - Convention: for CONFIRMED findings, run the finding past 2-3 independent readers of this brief (or re-read it yourself with fresh eyes after a break) and take the majority severity vote when they disagree, same as this pass's refuter votes did for A06-1 (MED/LOW/LOW → LOW).
