## Scope and lens

**From 19 (verbatim, all paths still current):** SCOPE: `components/**`, `app/**` UI, `lib/` UI labels, any place a DB enum/UUID/status reaches the screen. LENS: Any raw UUID / DB enum value / snake_case key / null/blank rendered to the user instead of an es-AR label (the case-kind class)? English leaking into user-facing UI (the English-code/Spanish-UI invariant broken)? Date/number formatting non-es-AR (comma decimals, dot thousands, DD/MM)? ## Method

1. **Raw-value leak sweep.** `rg -rn "\{[a-zA-Z]+\.status\}|\{[a-zA-Z]+\.kind\}|\{[a-zA-Z]+Id\}" components app -g '*.tsx'` (adjust the pattern per what you find) for JSX interpolating a raw enum/id field directly — the "case-kind class" this lens is named for. Cross-check each hit against a labeling helper/map that should have been used instead.
2. **English-in-UI sweep.** `rg -rn '"[A-Z][a-z]+ [a-z]+' components app -g '*.tsx' -g '!*test*'` as a rough heuristic for English sentence-shaped string literals in JSX — manually filter for genuine user-facing English (not code comments, not test fixtures, not prop names).
3. **Date/number formatting.** `rg -rn "toLocaleDateString|toLocaleString|Intl\.NumberFormat" components app apps/mobile/src` — for each, confirm the locale argument is `es-AR` (or a shared helper that defaults to it), not `undefined`/`en-US`.
4. **Design-token fence teeth.** Read `scripts/check-design-tokens.ts` and `scripts/check-design-token-parity.ts` in full. For the parity check specifically: does it actually diff web CSS custom-property values against `apps/mobile/src/ui/theme.ts`'s values token-by-token, or only check that both files declare the SAME SET of token names (a weaker guarantee — same names, different values, would pass)?
5. **Brand casing.** `rg -rn "MiMAR|\bDIM\b" components app apps/mobile/src -g '*.tsx' -g '*.ts' -g '!*test*'` — for each hit, confirm whether it's user-facing (a defect) or internal (fine per CLAUDE.md: "the internal codename DIM is fine in code paths and audit prose"). Read `scripts/check-brand-casing.ts` to see its own allowlist logic and compare against your manual sweep for any gap.
6. **Pluralization.** Read `scripts/check-pluralize-es.ts` in full for its rule, then spot-check 5 count-driven UI strings (e.g. "N mascotas") for correct es-AR pluralization at N=0, 1, 2.
7. **Hardcoded strings.** For 3-4 components, check whether copy is inline JSX text or pulled from a centralized copy/labels module (`scripts/check-copy-contract.ts` — read it for what "centralized" means in this codebase's convention).
8. **Timezone/locale on mobile.** `apps/mobile` uses React Native, not the DOM — confirm date/number formatting there uses the same `es-AR` convention via whatever RN-compatible formatting helper exists (`rg -rn "Intl\.|toLocaleDateString" apps/mobile/src`).
9. **Exploit or mutation per finding.** For a raw-value leak, show the literal snake_case/UUID/English string a real user would see on screen.
10. **At least 3 healthy items**, each with the guard traced and verified (a fence, a centralized label map).
11. **Triage every prior.**

## Output

Produce a JSON object (or equivalent structured notes) with these top-level keys:

- **findings**: array of `{id: "C07-n", title, severity: CRITICAL|HIGH|MED|LOW, kind: convention|doc-drift|bug, canonRule?, path, line, evidenceCmd, evidenceOutput(≤400ch), exploitOrMutation, fix(one line), fixClass: doc-fix|code-sdd|fence-candidate|po-decision, priorId?, priorStatus?}`
- **healthy**: array of `{title, property, path, line, evidenceCmd, evidenceOutput, whatWouldBreakIt, guardedBy, guardVerified: bool}` — minimum 3
- **priorTriage**: array of `{priorId, status: closed|still-open|not-reproducible, evidence}` covering every prior
- **nits**: array of `{path, line, note}`
- **coverage**: `{filesRead: [...], areasNotReached: [...]}`

**Severity rubric**:
- CRITICAL: not typical for this lens — a UI-copy defect rarely reaches CRITICAL; reserve for a raw internal identifier leak that itself constitutes a PII/security disclosure (cross-file with A06 if so, don't double-count).
- HIGH: a raw DB enum/UUID visible to end users on a high-traffic screen (the public credential, the crisis flow), stale "MiMAR"/"DIM" branding on a page an official or the public sees.
- MED: English leaking into a secondary/admin screen, a locale-formatting bug with a bounded (non-crisis) surface, a mobile/web token-parity NAME match that isn't a VALUE match.
- LOW: pluralization edge case, hygiene, hardcoded string with no observed inconsistency yet.

This brief is meant to be runnable by hand by someone who has not seen this workflow — if a step above is ambiguous without prior context, treat that as a bug in the brief and resolve it the most literal way rather than guessing at intent.
