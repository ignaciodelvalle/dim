## Method

1. **Enumerate the surface.** Run the scope's own `rg` command, plus:
   - `rg -n 'FUNCTION public.(export|erase)_subject_data' db/migrations/*.sql` and `rg -ln 'FUNCTION public.erase_subject_data' db/migrations` to find the CURRENT (latest-migration) body of each RPC — later migrations may only ALTER GRANTs, so confirm which file holds the live `CREATE OR REPLACE`.
   - `rg -n 'FUNCTION pii.caller_is_admin'` to find the admin-bypass predicate and diff it against known-correct sibling predicates (e.g. `rg -n 'deleted_at IS NULL' db/migrations/0188*.sql`).
   - `rg -ln 'requireLiveUser|requirePetAccess|auth\.getUser\(\)' src lib app` to map every entry point's lockout mechanism, and specifically hunt for bare `auth.getUser()` calls that skip `requireLiveUser`'s `deletedAt`/`deactivatedAt` check.
   - `rg -n 'dato removido|FREE_TEXT|sentinel' db/migrations/*.sql __tests__` to find the free-text redaction sweep, then cross-reference every `z.string()` leaf in `lib/events/*.ts` and `lib/events/custody-event-schemas.ts` against it (watch for `z.enum`/`z.boolean` false positives — a name like `*_reason` is not automatically free text).
   - `rg -ln 'overlayAmendments|amendment' lib/projections lib/metrics lib/analytics` to check whether the append-only amendment overlay is applied at every read path or left to caller discipline.
   - `rg -n 'Sentry\.(setUser|captureException|addBreadcrumb)' apps/mobile` (scope the search to the WHOLE `apps/mobile` tree, not just `apps/mobile/src` — check `apps/mobile/app/_layout.tsx` too) and `rg -n 'AsyncStorage\.(setItem|multiRemove)' apps/mobile/src` for the mobile erasure teardown.

2. **One command per claim, cited verbatim.** Every finding and every healthy item needs an `evidenceCmd` you actually ran and its `evidenceOutput` pasted (trim to the load-bearing lines, keep line numbers). Never assert a line number, a predicate, or a code shape from memory.

3. **Count with the fence's own method, not your reading of the prose.** For coverage-style fences (`check-subject-rights-coverage.ts`), read the classification function itself (e.g. `checkClassification`) and determine exactly what combination of memberships it fails on — do not trust the header comment's description of what it proves. Distinguish a table's EXPORT-side coverage from its ERASE-side coverage separately; a table reached by only one RPC is a distinct defect from a table reached by neither, and a fence that cannot tell the two apart is itself a finding (kind: `fence-gap`).

4. **Exploit or mutation per finding.** State a concrete actor, state, and request/action that reaches the defect (for a security finding, an attacker's exact RPC call or route hit with what bearer/state; for a fence-gap, the exact schema/table change that the fence would wave through; for a doc-drift, the exact reader decision the false sentence would produce).

5. **At least 3 healthy items with a verifiable guard.** For each, name the property in one sentence, the exact `path:line`, the test file that guards it (`guardedBy`), and try at least one concrete way to break it (a plausible refactor or code change) — state what test would catch that break and cite the assertion (file:line). Mark `healthyStatus: VERIFIED` only if you actually confirmed the guard test contains an assertion that would fail under the named break; otherwise mark `NOT VERIFIED` and say why (e.g. the guard file exists but doesn't test this specific property).

6. **Triage every prior finding.** See Priors above — all 16, no skipping.

7. **Severity rubric** (apply consistently):
   - **CRITICAL**: unauthenticated or trivially-reachable data exposure/destruction across subjects, or an invariant violation (a spine DELETE) reachable in production.
   - **HIGH**: an authenticated-but-unauthorized actor (wrong role, erased/deactivated account, cross-tenant) can read or act on another subject's art. 14/16 data; or a fence gap that structurally cannot detect the exact defect class it exists to catch.
   - **MED**: a real but bounded/mitigated residual (partial redaction, one-sided coverage with some visibility, a convention with no enforcement but a demonstrated single instance), or a doc/comment that would mislead an engineer into an unsafe change.
   - **LOW**: a debt item, an unresolved-but-written-down tradeoff, or a hygiene gap with no live caller currently affected.
   - Do not inflate severity for a finding whose core claim a majority of independent re-readings would refute on a load-bearing point (e.g. a documented, tested retention decision misread as an oversight) — file it as refuted, not downgraded.
