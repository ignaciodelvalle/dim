## Method

1. **Recount the event catalog** with `EVENT_TYPES.length`, not a grep — read `packages/contract/src/events/event-types.ts` in full and count the array literal by eye as a cross-check against the fence.
2. **Payload validation coverage.** For each of the 55 event types, confirm `lib/events/event-schemas.ts`'s big record has a matching Zod schema — `rg -n "eventType ===|case \"" lib/events/event-schemas.ts` vs the type list; any type with no schema entry is an unchecked-jsonb finding.
3. **Upcast/versioning.** Read `lib/event-upcasters.ts` (if present) and the `payload_version` convention in `event-schemas.ts`'s header comment — confirm the upcaster registry actually has an entry for every schema whose `payload_version` literal is >1.
4. **Asiento field whitelist.** Read `components/pet-profile/asiento-fields.ts` in full. For each event type rendered, confirm only whitelisted fields reach the DOM — `rg -n "payload\." components/pet-profile` for any direct payload access bypassing the whitelist.
5. **Contract purity.** Read `scripts/check-contract-purity.ts` in full for its exact rule (which imports it forbids, from which directory) — then independently `rg -n "from ['\"](@/|next|app/)" packages/contract/src` for any import the rule might miss by pattern.
6. **Web+mobile consumer parity.** `rg -rcln "@dim/contract" app lib src` and `rg -rcln "@dim/contract" apps/mobile/src` — for 3 sampled exports (a type, a schema, a constant), confirm both sides consume the SAME export rather than each maintaining a parallel copy.
7. **Payload parity fence.** Read `scripts/check-event-payload-parity.ts` in full — what does "parity" mean here (web vs mobile payload shape? schema vs DB enum?) — don't infer from the name.
8. **Enum drift.** `rg -n "pgEnum.*event_type|CREATE TYPE.*event" db/schema.ts db/migrations/*.sql` to find the DB-side enum (if one exists) and diff its value list against `EVENT_TYPES`.
9. **Exploit or mutation per finding.** For an unvalidated-payload finding, state what a malformed/malicious payload at that event type would do downstream (rendered raw, stored unchecked, read by a projection that assumes a shape).
10. **At least 3 healthy items**, each with the guard traced and verified.
11. **Triage every prior**, re-deriving the "48 vs 55" discrepancy as its own explicit triage line (it is likely `not-reproducible` as originally stated, superseded by the corrected 55).

**Severity rubric**:
- CRITICAL: an event type with an unchecked jsonb payload that reaches a privileged write or the asiento whitelist leaks a raw internal id/hash/PII field to the public credential view.
- HIGH: a payload field read but never validated on a reachable write path, an enum drift that could insert a value the DB rejects or silently miscategorizes, a `packages/contract` purity violation that creates a circular or framework-coupled dependency.
- MED: missing upcaster for a versioned schema with no live offending event yet, a web/mobile parity gap with a bounded (non-PII) blast radius.
- LOW: doc-drift (a stale count in a comment), hygiene.
