## Method

1. **Projection purity.** Read `lib/projections/pet-compliance.ts` in full. Confirm every exported compute function takes `(events, ...filters)` and returns a value with no hidden read of a cached column as an input (that would make it non-re-derivable).
2. **`rederivePetCache` boundary.** Read `lib/infra/rederive-pet-cache.ts` in full — which `pets.*` columns does it claim to own ("SOURCE OF TRUTH per column")? Cross-check against invariant 3's honest-hybrid wording: caches "declare themselves" — does every column this file writes have an explicit declaration, and does every column NOT covered have a documented reason (e.g. it's curated metadata, not event-derived)?
3. **Drift detector.** Read `scripts/detect-pet-cache-drift.ts` — what does it actually compare, and is it wired into `pnpm verify` (`rg -n "detect-pet-cache-drift" package.json`) or a standalone/manual script?
4. **Cache-write census.** `rg -n "\.update\(pets\)|\.set\(\{" lib src/modules app/actions -g '*.ts' -g '!*test*'` for every write to the columns named in 22's scope, then for each, check the SAME function/transaction for a paired `pet_events` (or `db.insert(petEvents`) call.
5. **`overlayAmendments` consumers.** `rg -rln "overlayAmendments" lib src` to get the current consumer list, then `rg -rln "pets\.\w+" lib/analytics lib/metrics -g '*.ts' -g '!*test*'` for dashboard/metrics code reading a cached column directly WITHOUT going through the amendment overlay — a candidate drift/finding class (a dashboard quoting a stale cached value instead of the amended one).
6. **Determinism and totality.** For 2-3 projection functions, check: does the function handle every event type in its domain (a `switch` with no `default` that silently ignores unknown types), and is event ordering respected (sorted by a stable key before folding, not insertion order of a query with no `ORDER BY`).
7. **Exploit or mutation per finding.** For a drift finding, give the concrete sequence: which write lands without its event, what an observer of `pet_events` alone would then compute (missing the change) vs what the cache actually shows.
8. **At least 3 healthy items**, each with the guard traced (a paired-write test, the drift detector, a repo convention with no counter-example found after a real search).
9. **Triage every prior.**

**Severity rubric**:
- CRITICAL: a compliance-relevant cache column (rabies, PPP, sterilization) written without its event, causing a legal-status projection to be wrong in a way that could mislead an official.
- HIGH: any `pets.*` cache column write with no paired event, reachable by a normal write path (the drift class 22 was built to find).
- MED: a dashboard/metrics read of a cached column that bypasses `overlayAmendments` where amendments are possible, or a projection with a non-total switch (silently ignores an event type) with no observed bad output yet.
- LOW: a drift detector gap with no live offender, hygiene.
