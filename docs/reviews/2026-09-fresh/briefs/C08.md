## Method

1. **Verify vs test:verified vs test.** Read `package.json`'s `verify`, `test`, `test:unit`, `test:verified` scripts in full (not from memory). Read `scripts/run-verified-suite.ts` and `scripts/check-suite-coverage.ts` in full — how does the verdict get computed, and what specifically would a worker crash look like in its output (cross-reference CLAUDE.md's DoD section for the exact three-signature framework it documents, and check whether the scripts' actual behavior matches that framework).
2. **`apps/mobile` coverage gap.** Confirm `apps/mobile/jest.config.js` has no `testTimeout`, then read `package.json`'s `verify:mobile` script (part of the `verify` chain per `AGENTS.md` line ~1428+) — does `test:verified` actually invoke `verify:mobile`'s test run, or are they two separate, never-reconciled gates? `docs/agents/recommendations-2026-08-30.md` §5 already claims a gap here — recheck it fresh.
3. **Brittle source-DOM guards.** `rg -ln "querySelector|getByTestId|container\.innerHTML" __tests__ -g '*.test.ts' -g '*.test.tsx'` — sample 5-8 and assess whether each asserts on a stable contract (a `data-testid`, an ARIA role) or a fragile structural detail (a specific nesting depth, a class name) that would break on an unrelated refactor.
4. **Test hermeticity / TEST-SS.** `rg -ln "beforeAll|afterAll|beforeEach|afterEach" __tests__/rls -g '*.test.ts'` — for the DB-touching test files, confirm each cleans up its own rows (not relying on transaction rollback alone if the test framework doesn't guarantee it) and doesn't share IDs that could collide under `--pool=threads` concurrency.
5. **e2e crisis-path coverage.** `ls e2e/*.spec.ts` (verified: 45 files including `e2e/demo/` and `e2e/perf/` subdirectories via `find e2e -name "*.spec.ts" | wc -l`) — read `e2e/README.md` in full for its own stated rules (seams, cleanup, real-token discovery, no hardcoded fixtures), then confirm `crisis-public.spec.ts` and `crisis-owner-lost-flow.spec.ts` actually exercise the lost/found and public-credential crisis paths end to end (not just smoke-test that a page renders).
6. **RLS matrix completeness.** `rg -ln "SELECT|INSERT|UPDATE|DELETE" __tests__/rls -g '*.test.ts'` — for a sample of tables, confirm BOTH a read-denial test and a write-denial test exist (a read-only matrix is a common half-finished state).
7. **Untested critical paths.** For auth, PII boundary, and event-integrity code (`lib/supabase`, `lib/utils/dni-hash.ts`, the append-only trigger's audited-override path), confirm each has a DIRECT test exercising its failure mode, not just incidental coverage from an unrelated feature test.
8. **Paint-bug gap.** Confirm whether any visual-regression/screenshot mechanism exists (`rg -rln "toMatchSnapshot\|screenshot" __tests__ e2e`) — if none, this is the LENS's own named gap: state which class of pure-CSS/paint bug would ship with zero test coverage today.
9. **Exploit or mutation per finding.** For a brittle-guard finding, name the innocuous refactor that would break it. For an untested-path finding, name the specific defect that could ship silently.
10. **At least 3 healthy items**, each with the guard traced and verified.
11. **Triage every prior.**

**Severity rubric**:
- CRITICAL: a critical path (auth, PII boundary, event-integrity override) with genuinely zero test coverage of its failure mode, reachable in production.
- HIGH: a false-green gate — a fence/test that reports pass regardless of the underlying property (test-theater), `apps/mobile` genuinely excluded from the DoD gate with no compensating control.
- MED: a brittle guard likely to generate false-negative noise on refactor, an incomplete RLS matrix (write tested, read not, or vice versa) with no live bypass demonstrated, `CONTRIBUTING.md` presenting `pnpm test` as sufficient when it isn't.
- LOW: hygiene, a documented (not silently misleading) scope limitation.
