## Method

1. **Enumerate 'use client' boundaries.** `rg -l "'use client'" components app` — for each, check the component actually needs client-side interactivity (state/effects/browser APIs), not just convenience.
2. **Non-serializable props.** For every Server→Client boundary found, `rg -n "function|=>|new Date|class " <ClientComponent props usage>` to look for function/class/Date props crossing the boundary.
3. **Hydration determinism.** `rg -n "Date\.now|Math\.random|window\.|matchMedia" app components --glob '!*test*'` for reads during render (not inside `useEffect`) — each hit needs a manual read of surrounding code to confirm it runs at render time vs effect time.
4. **RSC waterfalls.** For each `page.tsx`/`layout.tsx` with 2+ `await`s of independent data, check whether they're sequential (`await a(); await b();`) or parallelized (`Promise.all`/`Promise.allSettled`).
5. **Server action enumeration and validation.** `rg -l '"use server"' app src/modules` — for each exported action, confirm a Zod (or equivalent) `.parse`/`.safeParse` call runs before the first DB write; confirm an auth guard (`requireLiveUser` or equivalent) runs before the parse, not after.
6. **`revalidatePath`/`redirect` discipline.** `rg -n "revalidatePath|redirect\(" app src/modules` — flag any inside a `try { } catch` that could swallow the throw `redirect()` performs internally (Next's redirect works via thrown `NEXT_REDIRECT`; a catch-all `catch (e) { return {error} }` without a rethrow of redirect errors silently eats navigation).
7. **Route handlers and middleware.** Read `middleware.ts` in full for its matcher and CSP/header logic. `rg -ln '^export async function (GET|POST|PUT|PATCH|DELETE)' app --glob 'route.ts'` to enumerate.
8. **Fence coverage.** Read `scripts/check-action-line-budget.ts`, `check-action-redirect.ts`, `check-server-action-exports.ts` in full — what pattern makes an offender pass silently? Search for that pattern.
9. **Exploit or mutation per finding.** State the concrete actor/input sequence and the resulting effect (stale UI, unvalidated write, hydration mismatch causing a visible flash or a security-relevant branch divergence).
10. **At least 3 healthy items**, each with a verified guard traced from entry point to the check that would refuse/catch the defect.
11. **Triage every prior**, including unglamorous still-open ones.

**Severity rubric**:
- CRITICAL: an action mutates data with no auth guard reachable by any caller, or trusts a client-supplied role/jurisdiction/id with a privileged effect.
- HIGH: missing input validation before a DB write on a reachable action, or a hydration bug that causes a security-relevant UI branch (e.g. a privileged control) to render before the real check resolves.
- MED: a validation/guard gap bounded by a downstream check, a waterfall with a real latency cost, a redirect/revalidate bug causing stale (not wrong) UI.
- LOW: convention drift, hygiene, non-serializable prop with no observed runtime effect.
