# `docs/reviews/` — index of review generations

> Snapshot: `b975f3e9d` (`main`; `11c0ffc57` pushed 2026-09-02 plus `lenses/A01.md`) · Audited SHA: `d7dbf25f7` (lenses ran before WU-0 merged) · Facts: `docs/architecture/facts.json`
> Status: draft — finalized 2026-09-02 by the synthesis writer; fresh review fixes applied 2026-09-02

Every adversarial review, QA round and audit this project has run, oldest first. **Nothing in this directory is ever moved, renamed or deleted** — a superseded result is still the evidence a later finding was triaged against, and several 2026-09 findings cite a 2026-07 result file by path and line. This page is the map; the files are the record.

Three shapes live here:

- **Loose dated files** (`docs/reviews/2026-07-05-*.md` … `2026-08-18-*.md`) — one file per review run, named for the day it ran.
- **`results/`** — the outputs of the numbered topical audits (`01-*.md` … `28-*.md`, plus three `*-rerun.md`) and the dated consolidations, screenshot bundles and per-scenario reports of the QA waves.
- **`briefs/`** — the prompts those numbered audits were dispatched with. Its own `README.md` maps all 28 onto the 2026-09 lenses.

Two subtrees are self-contained and have their own entry points: `native-readiness/` (the Android-pilot readiness study) and `2026-09-fresh/` (the current audit).

## How to find something

- **"Was this ever reviewed?"** → `briefs/README.md` maps the 28 topical subjects onto the 2026-09 lenses and says which of them actually ran.
- **"What is the current state of finding X?"** → `2026-09-fresh/FINDINGS.json` for anything the 2026-09 audit touched; its `priorId`/`priorStatus` fields point back into `results/`.
- **"What can we say to officials?"** → `2026-09-fresh/DECK-FACTS.md`, which separates refuter-surviving claims from claims the audit found we cannot make.
- **"What should we fix next?"** → `2026-09-fresh/BACKLOG.md`, ranked by severity then blast radius, with the open PO decisions listed separately.
- **Live-environment questions** (RLS actually enabled, policies actually applied) are answered by generation 10 and by nothing since: every audit after it read source at a SHA and was forbidden from querying a database.

## Reading rules this directory has earned

1. **The triage file outranks the raw pass.** Generations 8, 15 and 17 all ended with a verification step that cut the raw finding count roughly in half or corrected the diagnosis. If both exist, read the triage.
2. **A closed finding answers "does the old reproduction still work?"** It does not answer "is the invariant enforced?" — generation 3's CRITICAL was correctly closed, and its class was found alive on a different path two months later, in generation 20.
3. **Counts are not comparable across generations.** A "finding" in generation 1 is one reviewer's unrefuted claim; a "finding" in generation 20 survived three independent refuters. Severity floors differ per review. Do not add them up.
4. **Screenshot bundles are evidence, not decoration.** Generation 13's `measurements-*.json` files are the only record of a regression that no test could see.
