## Recording rules applied (deviations from the 2026-07-01 draft)

- **Additive mutations film end-to-end** (denuncia, intake, adoption listing,
  new service + schedule rule, new investigation, org cases). **Story-
  destructive actions show the screen but never submit** (mark lost/found,
  deaths, transfers, cola approvals, moderation) — protecting the curated
  demo dataset the takes depend on.
- App-reality corrections: org intake has no photo field (photo shows in the
  maltrato evidence step instead); new offerings are approval-gated so the
  schedule rule lands on the first approved offering; `/admin/jurisdicciones`
  is now `/admin/reglas`; `/gob/campanas` is a read-only dashboard.
- Segment 05's investigation walks the ENO disease list until one opens
  (one open investigation per disease per jurisdiction), so re-records
  never trip the duplicate guard.
- `submitAndWait` helper works around hydration-dropped clicks (task #39)
  on every filmed submit; `loginAs` hardened the same way.

## Re-recording

Server must be FRESH (memory leak, task #38): kill :3333 first, then run
the segment — the config's webServer starts a new process from the current
`.next` build. Segments mutate additive data; takes stay coherent because
every spec is idempotent against its own residue.
